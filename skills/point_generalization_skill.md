# Skill: 点要素综合（VLM + LLM 联合决策与验收）

## 1. Skill 定位
本 Skill 用于**任意点要素数据**（如地铁站、医院、学校、POI、监测站、设施点等）的地图综合。
核心目标不是“单纯删点”，而是：
1. 先识别点要素的空间结构；
2. 再结合语义类型（点代表什么业务对象）；
3. 最后选择合适算法并给出可解释输出；
4. 使用视觉模型（VLM）+ 语言模型（LLM）做双重验收。

---

## 2. 总体流程（必须执行）

### Step A0: 导入 map-generalization 规范（新增强制）
每次点综合都必须先继承 `map-generalization` 的尺度与可读性规则，再进入点专项决策：
- 目标比例尺必须先吸附到最近国家基本比例尺档：`1:500/1:1000/1:2000`、`1:5000/1:10000`、`1:25000/1:50000/1:100000`、`1:250000/1:500000/1:1000000`；
- 只允许在同一国家基本比例尺序列内插值，不允许跨档位激进外推删点；
- 先算源/目标比例尺比值，避免“一步到位”大跳变参数；
- 约束最小符号间隔（按目标比例尺换算地面距离）；
- 先做选择/类型化，再做冲突消解与位移；
- 每轮操作后重新检查视觉冲突与结构完整性。

标准化参数建议（可按专题图微调）：
- 最小点符号间隔：`>= 0.30 mm`（图上）
- 点符号推荐尺寸：`0.4–0.8 mm`（图上）
- 同屏冲突对下降目标：`>= 60%`
- 点保留率安全下限：交通廊道 `>= 22%`，均匀监测 `>= 20%`，团簇 POI `>= 16%`
- 区域覆盖优先：先保“区域出现过点”的事实，再做热点压缩和局部冲突消解

小比例尺严格规则（新增）：
- 当目标比例尺 `>= 1:200000` 时，点冲突目标设为 `0`；
- 若 VLM/规则验收检测到遮盖冲突，必须继续迭代或降采样，直到“无重叠”。
- 在高密热点区可执行 RGB 过密检测（红色点符号局部占比），局部超阈值时优先压缩到约 `1/3` 代表点。

### Step A: 数据理解（输入诊断）
输入至少包括：
- 点图层（geometry）
- 比例尺信息：源比例尺 / 目标比例尺
- 属性字段（名称、等级、类别、功能、客流/权重等）

检查项：
1. CRS 检查：若为地理坐标系（如 EPSG:4326），先自动选择合适投影（优先 UTM）再做距离与密度计算。
2. 属性可用性：识别可用于语义评分的字段（如 `type/class/level/name/line/importance/weight`）。
3. 分布统计：全局密度、局部热点、最近邻距离分布、聚类倾向。

### Step B: VLM 结构识别（空间形态判别）
使用 VLM 对综合前可视化图（或栅格快照）识别点分布结构，输出结构标签（可多选）：
- cluster（团簇型）
- corridor（廊道/线性串珠型）
- center-periphery（中心-外围型）
- uniform（相对均匀型）
- multi-core（多中心型）

并输出结构置信度（0-1）及证据描述。

### Step C: LLM 语义识别（业务类型判别）
结合字段名、字段值、用户任务文本，识别语义类型，例如：
- 交通类：地铁站、公交站、铁路站、换乘枢纽
- 公共服务类：医院、学校、政务网点
- 商业类：商场、餐饮、零售 POI
- 风险监测类：传感器、告警点、事件点

要求输出：
- 语义主类型（primary semantic type）
- 关键子类型（如地铁站中的换乘站/终点站/普通站）
- 语义权重规则（谁优先保留）

### Step D: 结构+语义联合选算法
依据“空间结构 × 语义类型”选择点综合策略，而非固定算法。

## 3. 算法选择矩阵（核心规则）

### 3.1 地铁站 / 轨道交通站点（重点）
语义重点：换乘站、终点站、交通枢纽、中心城区关键站优先。
结构重点：沿线连续性、网络骨架、中心-外围平衡。

推荐算法组合：
1. 语义优先分层保留（Semantic Priority Selection）
2. 线网骨架保持抽样（Network Skeleton-preserving Sampling）
3. 局部拥挤区冲突消解（Displacement / Typification）

约束：
- 不允许删光某条线路关键控制段的代表站。
- 每条线路至少保留“端点 + 关键换乘点 + 若干中间代表点”。

### 3.2 团簇型商业 POI
语义重点：高等级/高影响力 POI。
结构重点：保持热点中心，不追求全量。

推荐算法组合：
1. 密度分层（热点/次热点/普通区）
2. 分区配额保留（Region Quota Selection）
3. 聚类代表点提取（Cluster Representative Selection）
4. 网格均衡补点（Grid Balance Compensation）
5. 热点轮廓锚点保留（Hotspot Contour Anchors）

强制约束（新增）：
- 不允许把高密度热点区“整体化解为空”；
- 每个热点区至少保留 1 个代表点；
- 每个有效区域至少保留 1 个代表点；
- 对输入中仅有 `1-2` 个点的稀疏小区域，综合后必须至少保留 `1` 个点，表示“该区域曾出现过该类点”；
- 对输入中约 `5-12` 个点的中密区域，不允许直接塌缩为 `1` 个点；应至少保留 `2-3` 个代表点表达局部结构；
- 对输入中 `>= 12` 个点的高密区域，不允许普遍只剩 `1` 个点；必须保留区内骨架或多代表点；
- 全图热点覆盖率（hotspot coverage ratio）需 `>= 0.50`；
- 热点代表点总数需 `>= 3`（或按图层规模动态提高）。

### 3.3 均匀分布监测点
语义重点：观测覆盖完整性。
结构重点：空间均匀性与覆盖孔洞控制。

推荐算法组合：
1. 抑制过密邻域（Min-distance thinning）
2. 覆盖约束采样（Coverage-constrained sampling）
3. 边缘补偿（Boundary compensation）

### 3.4 多中心城市设施点
语义重点：中心节点与次中心节点保留。
结构重点：多中心层级结构不塌缩。

推荐算法组合：
1. 分区分中心配额保留（Region Quota Selection）
2. 区内语义优先 + 区间平衡
3. 冲突消解后再验收

### 3.6 廊道型（中段保留专项，新增）
适用于你截图这种“沿主轴串珠+局部聚集”结构。  
核心目标：防止只保两端、丢失中段。

推荐算法组合：
1. 主轴估计（PCA）+ 轴向分箱（Axis Binning）
2. 每个有效轴向分箱至少保留代表点（优先高语义分）
3. 结合网格均衡补点，避免中轴连续段空洞

强制验收指标：
- 轴向覆盖率（axis coverage ratio）需 `>= 0.60`
- 中段最大连续空箱比例（middle gap ratio）需 `<= 0.35`

### 3.5 轮廓保真（所有点类型的强制约束）
无论语义类型为何，点综合都必须保留整体空间轮廓，不允许边界形态塌缩。

强制规则：
1. 保留边界控制点（至少 8 个方向锚点：xmin/xmax/ymin/ymax 及两条对角方向极值）。
2. 若 typification 或冲突消解后边界控制点丢失，必须回补这些点。
3. 若综合后凸包面积或长宽比变化超阈值，判定为轮廓失真，需要回滚重算。

## 4. 统一评分与决策模板
每个点计算综合分数：

`Score = w_semantic * S_semantic + w_struct * S_struct + w_visual * S_visual + w_balance * S_balance`

其中：
- `S_semantic`: 语义重要性（类别、等级、枢纽性、主题相关性）
- `S_struct`: 结构贡献（是否骨架点/边界点/中心点/关键过渡点）
- `S_visual`: 视觉冲突风险（过密区域惩罚）
- `S_balance`: 区域平衡补偿（稀疏区提升、区域缺失惩罚）

默认权重建议：
- 交通类（地铁站）：`0.40 / 0.30 / 0.20 / 0.10`
- 商业 POI：`0.35 / 0.25 / 0.30 / 0.10`
- 监测点：`0.25 / 0.25 / 0.20 / 0.30`

## 5. 分类型验收标准（必须在输出中声明）

### 5.1 通用验收
1. 可读性：符号冲突率下降到阈值内（例如冲突对数下降 > 60%）。
2. 完整性：无空图、无拓扑异常属性损坏。
3. 解释性：每个保留/删除决策可追溯（至少保留“主因标签”）。
4. 轮廓保真：边界控制点保留率必须为 100%，且轮廓形态变化在可控阈值内。
5. 主轴连续性：若识别为廊道/交通网络，必须通过“轴向覆盖率 + 中段空洞率”双阈值检查。
6. 区域覆盖：综合后区域覆盖率需足够高，不允许出现大面积“小区域整体消失”。

### 5.2 地铁站专项验收
1. 网络表达完整：关键线路骨架可辨识。
2. 枢纽保留率：换乘站/火车站/机场站等关键站保留率应为 100%。
3. 线路代表性：每条线路需满足最小代表站点数阈值。
4. 空间平衡：中心区与外围区保留比例不能极端失衡。
5. 轮廓控制：线路末端与边缘控制站点不得整体丢失（例如右下角边界点群应有代表站保留）。

### 5.3 商业 POI 专项验收
1. 热点中心不丢失。
2. 高等级 POI 保留率达到阈值。
3. 热点外区域仍有代表点，避免“只剩中心”。
4. 热点覆盖率 `>= 0.50`，且热点代表点数量满足最小阈值（默认 `>=3`）。
5. 稀疏区域覆盖率应高，输入仅 `1-2` 点的小区域不能被大面积清空。
6. 中密/高密区域不能普遍塌缩成单点，应保留至少局部骨架或多代表点。

### 5.4 监测点专项验收
1. 覆盖空洞面积不超过阈值。
2. 最近邻分布改善且不破坏观测网络均衡性。

## 6. VLM + LLM 双模型联合验收机制

### 阶段 1：VLM 验收（看图）
输入：综合前后地图截图、点密度热力图、线路叠加图（如有）。
输出：
- 结构保持评分（0-100）
- 可读性评分（0-100）
- 异常提示（如“中心塌缩”“边缘空洞”“骨架断裂”“稀疏区域消失”“中密区域塌缩为单点”）
- RGB 过密提示（如“右上热点红色像素过密，需继续化简”）

### 阶段 2：LLM 验收（看语义与规则）
输入：
- 保留/删除清单（含原因）
- 关键对象名单（如换乘站列表）
- 统计指标（冲突率、保留率、分区配额、区域覆盖率、稀疏区域覆盖率、密集区域塌缩率等）
输出：
- 规则符合性判定（pass/fail）
- 不合格条目与修正建议

### 阶段 3：联合结论
- 当 VLM 与 LLM 都通过：`accepted`
- 任一不通过：`revise_required`
- 输出必须包含：
  - `Completion status`
  - `Output files`
  - `Validation summary (VLM + LLM)`

---

## 7. 输出规范（Skill 执行产物）
每次执行必须输出：
1. 综合后数据文件（GeoJSON/Shapefile/GPKG）
2. 参数表（算法、阈值、权重、配额）
3. 验收报告（含 VLM + LLM 结果）
4. 决策解释表（点ID、是否保留、主要理由）

---

## 8. 失败回退策略
当出现以下问题时触发回退：
- 关键语义对象丢失（如地铁换乘站被删）
- 结构严重失真（骨架断裂、中心塌缩）
- 过度压缩（保留率低于类型下限）

回退策略：
1. 提升语义权重或关键对象硬约束；
2. 放宽局部最小间距阈值；
3. 恢复上一轮稳定结果并局部重算。

---

## 9. 推荐给 Agent 的简短系统提示（可嵌入）
你正在执行点要素地图综合。先用 VLM 识别空间结构，再用 LLM判定语义类型，基于“结构+语义”联合选择算法。对地铁站等交通点，必须优先保留换乘站/枢纽站并维持线路骨架。最终输出数据文件、参数表、决策解释表，并提供 VLM+LLM 双重验收结论。
